# deskpet 方案与路线

## 目标

deskpet 有两个用途：

1. **给 agent 用的工具**：让 agent 能够制作桌宠，包括生成资产、渲染预览、自动检查，并按"起稿、渲染、看图、改进"的循环迭代。
2. **给桌宠用的引擎**：在 macOS 桌面上以低功耗、高性能实时渲染并运行桌宠，按原生分辨率出图，保证高保真。

一套引擎支持两种风格：实物（写实）和动漫。电子风格已于 2026-11-03 决定不做。目前只做 macOS 桌面端。

## 参考：pixelfx

[pixelfx](https://github.com/patch-gg/pixelfx)（MIT）的思路是"代码就是素材"。每个特效是一个小文件，不用图片，通过参数（配色、随机种子、翻转）生成变体。它给 agent 配了一套闭环：

- `new` 生成起始模板；
- `render` 渲染联系表（contact sheet，一张图上排开多帧），agent 用看图能力检查效果；
- `check` 自动查出人眼容易漏掉的问题：画出画布、循环有接缝、随机数没固定种子、帧太慢；
- 一个 Claude Code skill，教 agent 按"起稿、渲染、看图、改进"的循环迭代。

pixelfx 的动作带"表演"数据：蓄力、命中定格、目标后仰、收势，全部写成时间轴数据。

deskpet 沿用这套闭环，把像素画换成原生分辨率的 3D 渲染。两种风格共用一个引擎，只换着色方式：

| 风格 | 着色 |
|---|---|
| 实物 | PBR 材质加毛发；可选高斯泼溅后端 |
| 动漫 | 卡通分层着色加描边 |

## 高斯泼溅

高斯泼溅适合实物风格，但不作为唯一方案。

- **优点**：能做出照片级的毛发和材质，网格模型很难达到。从一张或几张照片生成 3D 模型，现在的主流路线就是高斯泼溅。Rust 生态里可以参考 [Brush](https://github.com/ArthurBrussee/brush)（重建和渲染，基于 wgpu）、[wgpu-3dgs-viewer](https://github.com/lioqing/wgpu-3dgs-viewer) 和 [wgpu-gs-viewer](https://github.com/abist-co-ltd/wgpu-gs-viewer)。
- **难点**：要让模型动起来，得把每个高斯点绑到骨骼上，可参考 [brush_avatar](https://github.com/felixtaubner/brush_avatar) 和 [GTAvatar](https://github.com/KelianB/GTAvatar)。每帧还要按深度给几十万个点排序，GPU 开销比网格大。动漫风格用它效果反而不好。
- **决定**：引擎做双后端。网格是默认后端，两种风格都支持，也最省电。高斯泼溅作为实物风格的可选后端，复用同一套骨骼。为了省电，宠物空闲不动时不重新排序。

## 分阶段计划

### P1 引擎底座和省电（已完成）

- 按帧率预算调度渲染：事件循环只在下一帧到期时才请求重绘，其余时间休眠，不再空转。
- 按活跃程度分三档：交互中（满帧）、空闲、打盹（长时间没有交互后放慢呼吸，降低帧率）。窗口被遮挡时完全停止渲染。
- 功耗档位：`--power eco|balanced|smooth`，分别对应不同的三档帧率。
- 透明区域点击穿透：光标在宠物身上时窗口才接收鼠标事件，其他地方的点击直接落到下层窗口。
- 窗口和相机按宠物包围盒自动取景，减少透明区域，少画无用像素。

### P2 宠物资产格式和两种风格（已完成）

- 宠物包：一个目录，包含 `pet.toml` 清单、glTF 模型、风格参数和动作列表。
- 加载 glTF，支持骨骼蒙皮和表情 blendshape。
- 实物、动漫两套着色，用参数切换。
- 行为状态机：待机小动作、眨眼、视线跟随鼠标、点击反馈。动作时间轴参考 pixelfx 的 act 数据格式。
- 已实现说明：动作时间轴（蓄力、定格等）还没做，目前只按 glTF 动画剪辑切换；眨眼依赖模型自带闭眼 morph，示例狐狸没有，所以看不到。

### P3 给 agent 用的工具链（已完成）

- `deskpet new`：生成宠物包模板。
- `deskpet render`：离屏渲染联系表 PNG，覆盖多个角度、动作和风格，供 agent 看图迭代。
- `deskpet check`：检查资产，包括骨骼缺失、动作接缝、面数过高、帧时间超预算。
- 一个 Claude Code skill，教 agent 按"起稿、渲染、看图、改进"的流程制作宠物。
- 已实现说明：`check` 的帧耗时包含回读，偏保守；交互（点击、拖动、跟随）仍需真人试，skill 里写明了这一点。模型本身不生成，需要用户提供带骨骼动画的 glb。

### P4 高斯泼溅后端（已完成首版）

- 加载 `.ply` 或 `.spz` 格式的高斯模型，在 GPU 上排序并绘制。
- 把高斯点绑到骨骼上，复用 P2 的动作。
- 从照片生成模型这一步先调用外部工具（比如 Brush），deskpet 只负责导入。
- 已实现说明：PLY 导入、对齐、绑定最近顶点、CPU 基数排序（骨骼不动时跳过）、EWA 投影、`bake-splats`、`check` 的点数/排序耗时/对齐检查。未做：高阶球谐（颜色不随视角变）、GPU 排序、`.spz` 格式；2026-11-04 用一张 4K 照片经 SHARP 生成的点云验证过：能跟骨骼动、颜色是照片级，但单图背面缺失，且照片里狐狸的腿位置和模型不一致，Walk/Run 时腿部会撕开。要真正可用，需要多角度重建，或让模型的静止姿势贴合照片。

## 性能现状（2026-11-03，Apple M3）

已经用上的：
- **低功耗显卡和调度**：`PowerPreference::LowPower`，vsync，按帧预算重绘，三档降帧，遮挡停画。
- **Tile memory（无内存附件）**：MSAA 和深度缓冲标成 transient，在 Apple GPU 上是 memoryless，只活在片上 tile 内存里，不占显存、不走内存带宽。
- **QoS**：空闲时主线程 `QOS_CLASS_UTILITY`，内核把它放到能效核、低频率上跑；交互时切到 `USER_INTERACTIVE`。这一项让 balanced 空闲 CPU 从约 4% 降到约 1.9%。
- **零拷贝上传**：骨骼矩阵直接按 glam 内存布局上传。
- **缓存友好的排序**：高斯点用 4 遍 8 位基数排序，顺序扫内存。

采样分析结论：空闲时 CPU 时间绝大部分在内核等待（`__workq_kernreturn`、`mach_msg`），每帧我们自己的代码只有几十微秒。剩下的开销主要是 macOS 合成透明窗口和驱动提交，单靠 L1/L2 优化或多线程拿不到多少。

还能做的（按收益排序）：
1. **CAMetalDisplayLink / 可变刷新率**：让系统按需给帧，配合 ProMotion 把空闲刷新压到 10 Hz 以下。
2. **画面不变就不提交**：打盹时呼吸幅度小于半个像素就直接不画。
3. **GPU 排序**：点数到几十万时，把基数排序挪到 compute shader。
4. **点击穿透改为读回一像素 alpha**，省掉 CPU 蒙皮。

每个阶段结束都要编译、运行，截图并测量 CPU 占用。
